Frequently Asked Questions

❓ How does the User Access Matrix work?

The Access Matrix computes effective access rights (Read, Write, Create, Delete) by inspecting user groups, ACLs, and rules. It presents them in a clean color-coded grid so administrators can quickly audit system permissions without opening individual security rules.

❓ Can I find out who has Delete rights on sensitive models like Invoices?

Yes! Click on Reverse Search, enter the model name (e.g. account.move) and select the permission (e.g. Delete). The system returns an instant list of matching users along with their granted security groups.

❓ How does the User Permission Comparison tool work?

Select User A and User B from the popup modal. The tool calculates identical vs conflicting model permissions and highlights granular CRUD differences side-by-side, making onboarding or privilege auditing effortless.

❓ Does tracking actions degrade database performance?

No. The logging engine runs asynchronously and lightweight. For high-frequency models like stock moves or sales lines, you can easily disable tracking per-model using the built-in Audit Rules tab to keep performance fast.

❓ How fast does the One-Click Kill Switch take effect?

Instantly. Clicking "Kill Session" revokes the session token in the database. The affected user is force-logged-out on their very next click or page navigation.

❓ Is this module compatible with both Odoo CE and EE?

Yes, Super Session Management & Audit Trail is fully compatible with both Odoo 18 Community Edition (CE) and Enterprise Edition (EE).

❓ How do I manage audit log retention and database size?

The app includes an automated cron job that purges logs older than a configurable retention threshold (default 365 days), keeping database growth bounded.

💾 Storage & Performance Notes

This module tracks Create/Update/Delete operations across business models by default. Actual database growth depends heavily on usage volume and which models are tracked — typical ranges are 100MB-1.5GB/year for small-to-medium teams (10-50 users), up to 10-15GB/year for larger deployments with heavy inventory/manufacturing activity. A configurable retention policy (default 365 days) keeps growth bounded. For high-volume deployments, we recommend disabling audit tracking on line-item models (stock moves, order lines, journal items) via Audit Rules, which typically reduces log volume by 60-80% with minimal loss of audit value, since parent document state changes remain fully tracked.
